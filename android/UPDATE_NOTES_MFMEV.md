# MF-MEv Android — Team Handoff Notes

## Changes in this handoff
- Removed end-user Supabase URL/key editing from Login, Settings, and website-linking screens. Backend credentials are now treated as application configuration, not ordinary user settings.
- Removed the quick demo pairing bypass and sample JSON batch button/data from production UI.
- Removed the visible Supabase project identifier/status banner from end-user screens.
- Added WebView main-frame network error feedback, safe URL scheme checks, renderer-process crash recovery, and a Reload action that recreates the browser view.
- Preserved the existing application workflow, data model, platform-session flow, and evidence capture behavior.
- Kept unit/instrumentation test source files; these are automated checks, not user-facing demo data.

## Security / handoff
- The uploaded signing keystore was intentionally excluded from this handoff archive. Do not commit upload keys or passwords to source control. Team release signing should use secure CI secrets or a separately managed keystore supplied by the project owner.
- `.env.example` is a template only. Never commit a production `.env` file or service-role credentials. The Supabase publishable/anon key may be used in client apps only with correct RLS and server-side authorization.

## Important remaining verification
- This archive contains the Android app source only. The website source and deployed `mfp-evidence-linking` Supabase Edge Function were not included, so the server-side root cause of `Invalid Pairing Code` cannot be confirmed or fixed end-to-end here.
- Real-time user score still requires the authoritative score API/schema from the backend; no fake score or invented formula has been added.
- Android build and physical-device browser stress tests were not run in this environment because the uploaded project has no Gradle wrapper JAR and no system Gradle executable was available. Run `./gradlew test` and a debug build in Android Studio/CI before distributing an APK.

## Recommended team verification checklist
1. Build a debug APK in Android Studio.
2. Test Login with a real, unexpired pairing code generated by the website.
3. Test wrong, expired, already-used, and rate-limited pairing codes.
4. Open each supported platform in the in-app browser, navigate, capture evidence, and press Back.
5. Simulate loss of network and a WebView renderer crash; confirm the Reload UI appears and recovers.
6. Confirm all existing assigned-link, screenshot, export, sync, and account authorization flows still work.
